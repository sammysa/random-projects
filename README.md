## Contributing

Contributions are welcome!

If you find something that could be improved, have an idea for a new feature, or simply want to experiment with one of the projects, you are encouraged to contribute.

To keep the `main` branch stable and ensure that changes are properly reviewed, all contributions should follow the **feature branch and pull request workflow**.

### Contribution Workflow

#### 1. Create a Feature Branch

Create your own branch from `main` for the work you want to perform.

```bash
git checkout main
git pull
git checkout -b feature/your-feature-name
```

#### 2. Make Your Changes

Work on the project as you see fit. You are free to modify existing functionality, fix bugs, improve code, or introduce new features.

#### 3. Commit Your Changes

```bash
git add .
git commit -m "Add your change description"
```

#### 4. Push Your Feature Branch

```bash
git push origin feature/your-feature-name
```

#### 5. Create a Pull Request

Open a Pull Request from your feature branch into `main`.

#### 6. Code Review

The changes will be reviewed by the relevant **branch owner or repository administrator**.

#### 7. Merge

Once the changes have been reviewed and approved, the branch owner or repository administrator will merge the Pull Request into `main`.

## Main Branch Protection

The `main` branch is protected.

Contributors **must not merge directly into `main`**. All changes intended for `main` must go through a Pull Request and receive the required approval before being merged.

This allows contributors to work independently while keeping the `main` branch stable and ensuring that changes are reviewed before becoming part of the primary codebase.

## Branches

Contributors are encouraged to create descriptive branches based on the type of work being performed.

Examples:

```text
feature/new-login
feature/customer-dashboard
bugfix/api-validation
bugfix/database-connection
improvement/error-handling
experiment/new-framework
```

Please avoid committing experimental or incomplete work directly to `main`.

## Ideas & Improvements

You don't need to wait for permission to experiment with the code. **Fork it, branch it, build it, and submit your improvements for review.**
